API docs — how your apps check in

      

        
Base URL: 

        
1. Activate / check in (consumes 1 use, registers the device)

        
POST /api/license/verify
Content-Type: application/json

{
  "apiKey":   "SHADOW-XXXXX-XXXXX-XXXXX",
  "deviceId": "my-pc-01",
  "deviceMeta": { "app": "MyApp", "appVersion": "1.2.0", "platform": "windows" }
}

        
2. Status check (consumes nothing)

        
GET /api/license/verify?apiKey=SHADOW-XXXXX-XXXXX-XXXXX

        
Response (valid)

        
{ "valid": true, "key": "SHADOW-…", "expiresAt": null,
  "usesUsed": 3, "usesLeft": null, "deviceCount": 1,
  "maxDevices": null, "deviceRegistered": true, "message": "OK" }

        
Response (invalid)

        
{ "valid": false, "reason": "expired",
  "message": "This license has expired.", … }

        

          reason is one of: invalid_key, revoked, expired,
          max_uses, max_devices.
          


          Use a stable, unique device id per machine (e.g. a UUID you generate once and store in app
          settings, or a hash of the hardware id). Device ids are hashed with SHA-256 before storage.
          


          Full guide + code snippets (JS / Python): see README.md in the GitHub repo.
